## ⚠️ PRE-EXECUTION SAFETY GUARDS — applies to every task

These come from the project's hard-won lessons. Re-state in every dispatched implementer prompt.

1. **All `cargo`/`npm`/`git` commands run from the workspace root** (`/path/to/vibeflow`).
2. **Never use `git commit --amend`** — leaves invisible drift. New commits only. Controller runs `git status` after every task.
3. **Never delete tests or `#[allow(...)]` away clippy/rustdoc warnings** to make a build green. Fix the cause.
4. **Reviewer subagents are READ-ONLY**: no `git checkout`, no `rm`, no file edits, no `git reset`.
5. **No `cargo publish` / `npm publish` / `git push --tags` / `gh repo edit`** from any task. Those are the human-gated v0.1.1 finale (separate doc).
6. **The `Edit` tool is BLOCKED on `.github/workflows/*.yml`** by a security-reminder hook. Use `python3` heredocs via `Bash` for precise workflow edits (each task that needs this includes the exact script).
7. **CI flag parity**: locally run `RUSTDOCFLAGS="-D warnings" cargo doc --workspace --no-deps` — CI sets that and would fail on doc warnings (this is exactly what bit us between Stage 13 polish and v0.1.0).
8. **No emoji in committed files** unless explicitly requested.
9. **No backwards-compat shims, no "TODO later"**. YAGNI.

## Task 5: Strip `ESC[201~` from clipboard paste (TDD)

**Files:**
- Modify: `crates/vibeflow/src/clipboard.rs` (new `sanitise_paste()` function + tests)
- Modify: `crates/vibeflow/src/window.rs:705` (`handle_paste`)
- Modify: `crates/vibeflow/src/window.rs:727` (`handle_paste_primary`)

Codex finding #4 — bracketed paste mode wraps the pasted text with `ESC[200~` and `ESC[201~`. If the pasted content itself contains `ESC[201~`, the terminal sees an end-of-paste followed by raw input that an attacker controls — classic paste-injection vector.

Fix: strip `ESC[201~` (bytes `\x1b\x5b\x32\x30\x31\x7e`) from the inner paste text before it's sent to the PTY. Applies in both bracketed AND non-bracketed paths (defence-in-depth — non-bracketed text shouldn't contain the marker anyway, but stripping is harmless and keeps the invariant simple).

- [ ] **Step 5.1: Read the current `clipboard.rs` end** to find an insertion point

```bash
tail -15 /path/to/vibeflow/crates/vibeflow/src/clipboard.rs
```

The file ends with `}` after the existing `impl` blocks. Add a free function (not method) after the last `impl`.

- [ ] **Step 5.2: Write the failing tests FIRST**

Append to `crates/vibeflow/src/clipboard.rs`:

```rust

/// Remove every occurrence of the bracketed-paste end marker `ESC[201~`
/// (bytes `0x1b 0x5b 0x32 0x30 0x31 0x7e`) from clipboard text before it
/// is sent to the PTY.
///
/// Defence against a clipboard-paste-injection vector: a malicious paste
/// containing `ESC[201~` would otherwise terminate the bracketed-paste
/// frame mid-content, after which the terminal interprets remaining
/// bytes as live user input — and the application running inside reads
/// them as keystrokes the user did not type.
///
/// Removal (not substitution) preserves adjacent content byte-for-byte;
/// the marker is six bytes and removing it is the least-surprising
/// outcome for adjacent text. Also applied in the non-bracketed path —
/// the marker has no meaning there but stripping keeps the invariant
/// simple ("PTY never sees the marker via paste").
#[must_use]
pub fn sanitise_paste(input: &str) -> String {
    const MARKER: &str = "\x1b[201~";
    if !input.contains(MARKER) {
        return input.to_string();
    }
    input.replace(MARKER, "")
}

#[cfg(test)]
mod sanitise_paste_tests {
    use super::sanitise_paste;

    #[test]
    fn passthrough_when_no_marker() {
        assert_eq!(sanitise_paste("hello\nworld"), "hello\nworld");
        assert_eq!(sanitise_paste(""), "");
    }

    #[test]
    fn removes_a_single_marker() {
        let injected = "ls -la\x1b[201~rm -rf /\n";
        assert_eq!(sanitise_paste(injected), "ls -larm -rf /\n");
    }

    #[test]
    fn removes_multiple_back_to_back_markers() {
        let injected = "a\x1b[201~\x1b[201~b";
        assert_eq!(sanitise_paste(injected), "ab");
    }

    #[test]
    fn preserves_other_escape_sequences_unchanged() {
        // ESC[200~ (paste START marker) must NOT be stripped — only ESC[201~
        // is the paste-end marker we strip. Other escape sequences are also
        // out of scope for this defence (deferred per spec §2.4).
        let s = "\x1b[200~start\x1b[?1004hmid";
        assert_eq!(sanitise_paste(s), s);
    }
}
```
