**Date:** 2026-05-23
**Status:** Approved (brainstorm), pending implementation plan

Make vibeflow quiet by default on stderr (no more chatty `info!` lines leaking into the user's terminal) while preserving and extending diagnostic capability via a rotated file log at the XDG state directory. Implements the `// Stage 9 will add file logging + rotation.` TODO that never landed (see `crates/vibeflow/src/main.rs:41`).

## 1. Scope & non-goals

**In scope (v0.1.2):**

1. New module `crates/vibeflow/src/logging.rs` housing `pub fn init() -> Result<WorkerGuard>` and supporting helpers.
2. `main.rs:run_gui` replaces its inline `tracing_subscriber` wiring with a call into the new module.
3. Two-writer setup: a quiet stderr layer (`vibeflow=warn` by default) and an info-level file layer with daily rotation via `tracing-appender`.
4. File log path: `$XDG_STATE_HOME/vibeflow/vibeflow.log.YYYY-MM-DD` (defaults to `~/.local/state/vibeflow/...`). State dir created on init with `0o700` if missing.
5. `RUST_LOG` environment variable overrides BOTH layers' default filters.
6. Best-effort retention cleanup at init time: scan the state dir and delete `vibeflow.log.*` files older than 7 days.
7. Tests covering: state-dir creation + perms, retention cleanup, default-filter suppression of info on stderr, graceful degradation when file logging cannot init.

**Out of scope (with rationale):**

- **Size-based rotation** — `tracing-appender` only offers time-based. Daily rotation + 7-day retention bounds disk use adequately for a desktop app. Size-based rotation would require a third-party crate or hand-rolled writer; not worth the dep.
- **Structured JSON output** — current pretty/compact text formats are adequate for desktop-app diagnosis. JSON would help only if vibeflow logs were ever ingested by a log aggregator, which is not a use case here.
- **`--log-level` CLI flag** — `RUST_LOG` covers this and is the Rust ecosystem convention. A flag would duplicate the env var without adding value.
- **In-UI log viewer** — surfacing logs in the terminal UI is a UX project (when, where, with what filtering), not a logging project. Out of scope for v0.1.2.
- **CLI-path logging** — `--import-colors` and `--version` paths use `eprintln!` for arg errors and continue to. They don't init the GUI logger and shouldn't (logging arg-parsing failures to a file would be surprising).
- **`vibeflow-emit` CLI logging** — separate binary, no GUI, no log file. Stays on `eprintln!`.

## 2. Module structure

**New file:** `crates/vibeflow/src/logging.rs`

```rust
//! Vibeflow's logging facility: a quiet stderr + a rotated file log.
//!
//! Stage 9 deferred this; v0.1.2 (Spec A') implements it.

use anyhow::{Context, Result};
use std::path::PathBuf;
use tracing_appender::non_blocking::WorkerGuard;
use tracing_subscriber::{fmt, prelude::*, EnvFilter};

/// File log retention in days. Files matching `vibeflow.log.*` with mtime
/// older than this are deleted at init time (best effort).
const LOG_RETENTION_DAYS: u64 = 7;

/// Initialise vibeflow's logging subsystem.
///
/// Returns the `WorkerGuard` for the non-blocking file writer. The caller
/// MUST keep the guard in scope for the lifetime of the program — dropping
/// it flushes pending writes and shuts the worker thread down.
///
/// On failure to set up the file writer (e.g. no writable state dir), the
/// program falls back to stderr-only logging and returns Err for the caller
/// to log/ignore as appropriate.
pub fn init() -> Result<WorkerGuard> {
    let state_dir = state_dir().context("locate XDG state dir")?;
    ensure_state_dir(&state_dir)?;
    cleanup_old_logs(&state_dir);

    let file_appender = tracing_appender::rolling::daily(&state_dir, "vibeflow.log");
    let (file_writer, guard) = tracing_appender::non_blocking(file_appender);

    let stderr_filter = EnvFilter::try_from_default_env()
        .unwrap_or_else(|_| EnvFilter::new("vibeflow=warn"));
    let file_filter = EnvFilter::try_from_default_env()
        .unwrap_or_else(|_| EnvFilter::new("vibeflow=info,warn"));

    tracing_subscriber::registry()
        .with(
            fmt::layer()
                .with_target(false)
                .with_writer(std::io::stderr)
                .with_filter(stderr_filter),
        )
        .with(
            fmt::layer()
                .compact()
                .with_ansi(false)
                .with_writer(file_writer)
                .with_filter(file_filter),
        )
        .init();

    Ok(guard)
}

fn state_dir() -> Option<PathBuf> {
    dirs::state_dir().map(|d| d.join("vibeflow"))
}

fn ensure_state_dir(path: &std::path::Path) -> Result<()> {
    if !path.exists() {
        std::fs::create_dir_all(path).context("create vibeflow state dir")?;
        #[cfg(unix)]
        {
            use std::os::unix::fs::PermissionsExt;
            std::fs::set_permissions(path, std::fs::Permissions::from_mode(0o700))
                .context("set state dir perms")?;
        }
    }
    Ok(())
}

fn cleanup_old_logs(state_dir: &std::path::Path) {
    // Best-effort. Errors logged at WARN; init must continue.
    let cutoff = std::time::SystemTime::now()
        .checked_sub(std::time::Duration::from_secs(LOG_RETENTION_DAYS * 86_400));
    let Some(cutoff) = cutoff else { return };
    let Ok(entries) = std::fs::read_dir(state_dir) else { return };
    for entry in entries.flatten() {
        let name = entry.file_name();
        let Some(name_str) = name.to_str() else { continue };
        if !name_str.starts_with("vibeflow.log.") {
            continue;
        }
        if let Ok(meta) = entry.metadata() {
            if let Ok(modified) = meta.modified() {
                if modified < cutoff {
                    let _ = std::fs::remove_file(entry.path());
                }
            }
        }
    }
}
```

**`main.rs` change** (replaces `main.rs:42-47`):
```rust
let _log_guard = match vibeflow::logging::init() {
    Ok(guard) => Some(guard),
    Err(e) => {
        eprintln!("warning: file logging unavailable ({e}); using stderr only");
        // Fallback: stderr-only subscriber so the program isn't silent.
        let filter = EnvFilter::try_from_default_env()
            .unwrap_or_else(|_| EnvFilter::new("vibeflow=warn"));
        tracing_subscriber::registry()
            .with(fmt::layer().with_target(false).with_filter(filter))
            .init();
        None
    }

```

The `_log_guard` binding (leading underscore intentional — never read) MUST stay alive for `main`'s scope. Dropping it flushes the file writer and stops the background worker thread.

## 4. Default filter behavior

| Layer | Default filter when `RUST_LOG` unset | Rationale |
|---|---|---|
| stderr | `vibeflow=warn` | User-visible stream stays quiet. Only vibeflow's own WARN+ surfaces. Third-party (wgpu/winit/cosmic-text) WARN suppressed by default. |
| file | `vibeflow=info,warn` | Diagnostic stream captures vibeflow's INFO+ state-change logs PLUS third-party WARN+ for post-mortem context. |

**`RUST_LOG` override**: when set, replaces BOTH default filters. E.g.:
- `RUST_LOG=vibeflow=trace` — trace everywhere (both stderr + file).
- `RUST_LOG=vibeflow=info` — info everywhere.
- `RUST_LOG=debug` — third-party debug too (verbose).
- `RUST_LOG=vibeflow=warn,wgpu=error` — granular per-target.

The override applies symmetrically because both layers call `EnvFilter::try_from_default_env()` independently. A user wanting different stderr vs file filters can't do that via `RUST_LOG` alone — they'd need to wait for a future per-layer override syntax. Not in scope.

## 5. File layout

```
$XDG_STATE_HOME/vibeflow/      (0o700, created at init)
├── vibeflow.log.2026-05-23    (current day; tracing-appender daily rotation)
├── vibeflow.log.2026-05-22    (yesterday)
├── ...
└── vibeflow.log.2026-05-17    (7 days back; older auto-deleted)
```

- Filename pattern: `vibeflow.log.{YYYY-MM-DD}` — tracing-appender appends the date suffix automatically with `Rotation::DAILY`.
- Current-day file is appended to within the day; rotation happens at midnight local time when the next write occurs.
- Format: compact, no ANSI (file is for human reading + grep, not for terminal rendering). Each line:
  ```
  2026-05-23T14:32:11.234567Z  WARN vibeflow::window: xdg-open /tmp failed: ...
  ```

## 6. Retention

At init time, `cleanup_old_logs` scans `$XDG_STATE_HOME/vibeflow/` for entries matching the prefix `vibeflow.log.` and removes any whose `mtime` is older than `LOG_RETENTION_DAYS` (7) days before now. Failures (permission denied, race with another vibeflow instance) are silently swallowed — retention is best-effort, never fatal.

No retention by count (e.g. "keep last N files"). Time-based is simpler and matches the daily rotation semantics.

## 7. Test strategy

All tests in `crates/vibeflow/src/logging.rs::tests`.

- **`init_creates_state_dir_with_correct_perms`** — call `ensure_state_dir(&tempdir.join("vibeflow"))`; assert dir exists; on unix, assert mode is `0o700`.
- **`retention_cleanup_deletes_old_logs`** — pre-create `vibeflow.log.2024-01-01` and `vibeflow.log.<today>` in a tempdir; set the old file's mtime to 30 days ago via `std::fs::File::set_modified` (stable since 1.75, matches our MSRV — no extra dep needed). Call `cleanup_old_logs(&tempdir)`. Assert the old file is gone, the recent one remains.
- **`retention_ignores_non_matching_files`** — create `vibeflow.log.bak` and `README` with old mtime; assert they survive cleanup (only the `vibeflow.log.YYYY-MM-DD` pattern is targeted).
- **`default_stderr_filter_suppresses_info`** — install a custom test subscriber + capture stderr; emit `tracing::info!("test")`; assert no output. Emit `tracing::warn!("test")`; assert output present.
- **`rust_log_override_takes_effect`** — set `RUST_LOG=vibeflow=trace`, init logger to a buffer-backed writer, emit trace, assert output.
- **`fallback_init_on_state_dir_failure`** — set `XDG_STATE_HOME` to `/dev/null` or a path that can't be created; assert `init()` returns Err with a context message AND that vibeflow can continue (the fallback in `main.rs` keeps stderr-only logging alive).

Integration test (`tests/logging_integration.rs`) is overkill for v0.1.2 — unit tests cover the contract.

## 8. Risks & mitigations

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| `dirs::state_dir()` returns `None` on a system where `$HOME` is unset | low | logger init fails | fallback path in `main.rs` keeps stderr-only logging running; vibeflow remains usable. |
| Permission failure on existing state dir | low | retention skipped silently | best-effort — single missed cleanup not user-impacting. |
| Multiple vibeflow processes write the same daily log | medium | interleaved log lines | tracing-appender does line-level writes via `write_all`; interleavings are line-aligned, no torn lines. Acceptable. |
| `WorkerGuard` accidentally dropped early | low | file writer stops mid-program | bound to `_log_guard` in `main` for the program's whole scope; impossible to drop early without removing the binding. |
| `cargo test` writes to the user's real state dir | medium | test pollution | unit tests construct tempdirs explicitly; never call `init()` directly (only the helpers). |
| Disk full during write | low | file writes silently fail | non-blocking writer drops writes when its channel is full; doesn't stall the render loop. Logged once at next successful write. |
