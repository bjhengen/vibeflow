# vibeflow v0.1.3 — Confirm-on-close — design spec

**Date:** 2026-05-27
**Status:** Approved (brainstorm), pending implementation plan
**Branch base:** `main` @ `f678a77` (post-v0.1.2 ship)
**Target release:** v0.1.3
**Motivating incident:** 2026-05-27 — Brian's 3-tab daily-driver session vanished mid-work via an accidental window close (X-button or Alt+F4). No log signature distinguished it from a graceful exit because `WindowEvent::CloseRequested` currently calls `event_loop.exit()` unconditionally (`window.rs:1164`).

Add a modal confirm dialog before destroying a vibeflow window when there are sessions worth protecting. Mirrors iTerm2's protective default while staying out of the way for the single-idle-tab case.

> Code references (file:line) below were accurate at spec time on `main`
> @ `f678a77`; verify against current source before editing.

## 1. Scope & non-goals

**In scope (v0.1.3):**

1. New module `crates/vibeflow/src/render/confirm_close.rs` housing layout + rect/glyph builders for the dialog overlay (mirrors `render/about.rs`).
2. New module `crates/vibeflow/src/session/proc_watch.rs` helper: `pub fn foreground_pgid(child_pid: i32) -> Option<i32>` returning tpgid from `/proc/<child_pid>/stat`.
3. New `PtySession` accessor `pub fn has_foreground_child(&self) -> bool` computing `foreground_pgid(child_pid) != Some(child_pid)`.
4. New `WindowApp::busy_tabs(&self) -> Vec<BusyTabInfo>` walking all sessions.
5. `WindowApp.confirm_close: Option<ConfirmCloseState>` field; gating of `WindowEvent::CloseRequested`; key + mouse intercepts for the dialog.
6. New `[ui]` config section with one key: `confirm_on_close: bool` (default `true`).
7. Unit + integration tests; manual VNC smoke walk before merge.

**Out of scope (with rationale):**

- **Per-tab close confirmation** — closing a single tab via context menu doesn't go through `WindowEvent::CloseRequested`. v0.1.3 covers the window-close path only; per-tab is a separate (smaller) follow-up.
- **Idle-tab display in dialog** — hide entirely. The dialog is about *what would be lost*; listing idle bash tabs adds noise.
- **Auto-dismiss timer** — explicit user action only. No "Cancel after 10s" or similar.
- **Force-quit shortcut** — `Ctrl+Shift+Q` to bypass dialog forever this session. Not needed; the `confirm_on_close = false` config switch covers users who never want the dialog. Second-X-click rage-quit (see §3) covers the "I really mean it" moment.
- **Snapshot freshness** — dialog content is captured at open time. Tabs spawned mid-dialog don't update the list. Brief race; acceptable.
- **Non-Linux foreground detection** — `proc_watch` is Linux-only (per `proc_watch.rs:7-8` doc). On other OSes, `has_foreground_child` returns `false` (fail-open, never block close on a platform without detection). v0.1 doesn't target other OSes anyway.

## 2. "Busy" / "needs confirmation" logic

A **tab** is considered **busy** if EITHER:

- (a) `has_foreground_child()` returns `true` — i.e., `/proc/<child_pid>/stat` tpgid ≠ child_pid (something other than the shell has terminal control: `python3`, `vim`, `claude`, `make`, etc.), OR
- (b) `tracker_state()` ∈ {`Working`, `Waiting`} — mid-AI-work even if the FG check says shell (covers e.g. a `claude` REPL between prompts where bash briefly has terminal control).

A **close** requires confirmation if EITHER:

- The window has **more than one tab open** (iTerm2-style — multiple tabs imply intent, even if all are idle), OR
- **Any tab is busy** per the definition above.

Equivalently, a close is **silent** only when there is exactly one tab open AND that tab is not busy.

### 2.1 Why iTerm2-style (>1 tab) on top of busy-check

Konsole confirms only on FG-process; iTerm2 confirms on any multi-tab window. Brian's call: iTerm2 is more protective and matches the user's mental model that "multiple tabs = I've invested setup work here, double-check before discarding it". Single idle tab still closes instantly — that's the "ephemeral terminal" case where friction matters most.

### 2.2 Why both (a) AND (b)

- (a) alone misses claude/codex REPLs in their idle state (terminal returns to bash briefly between prompts).
- (b) alone misses non-AI work (vim, python REPL, long `make`).
- Union covers both. Cheap to compute (both are already plumbed by Stage 11 / `proc_watch`).

### 2.3 BusyTabInfo

```rust
#[derive(Debug, Clone)]
pub struct BusyTabInfo {
    pub tab_index: usize,         // 1-based for display ("Tab 1")
    pub display_label: String,    // e.g. "claude" or "python3" or "bash" if idle but multi-tab
    pub state_label: String,      // e.g. "Waiting", "running 4m 32s", "idle"
}
```

Computed at dialog-open time, immutable for the lifetime of the dialog.

## 3. UX (modal overlay, About-pattern)

Renderer addition mirrors `render/about.rs` exactly:

- Full-window backdrop dim (semi-transparent).
- Centred panel, default 560×320 px (clamped to window-40 on small windows, 8 px margin under 200×120 — same defensive sizing as About).
- Theme-aware colours via new `ConfirmCloseColors { backdrop, panel_bg, border_fg, text_fg, button_idle_bg, button_focus_bg, button_text_fg }`.

### 3.1 Content layout

Five-region layout, top-to-bottom:

1. **Title line** — `"Close vibeflow?"` (bold-equivalent via existing tabs-pipeline-style emphasis).
2. **Blank line** (visual padding).
3. **Summary line** — depends on dialog mode:
   - **Busy mode** (≥1 busy tab): `"{N} sessions are active:"` where N = `busy_tabs.len()`.
   - **Idle multi-tab mode** (no busy tabs, but tab count > 1): `"{N} tabs are open. Close all?"` where N = `app.session_count()`. No list region rendered (region 4 collapses).
4. **List of busy tabs** (busy mode only) — one line each: `"  • Tab {1-based-index} ({display_label})  — {state_label}"`. Cap at 8 rows; if more, last row reads `"  … and {n} more"`.
5. **Button row** — `[Cancel]   [Close anyway]`, right-aligned, with `Cancel` focused by default (highlighted background).

Panel height adapts: busy mode = 320 px default (room for ~8 list rows); idle multi-tab mode = 200 px default (no list region). Clamp/tiny rules in §3 introduction still apply.

### 3.2 Input handling

| Input | Effect |
|---|---|
| `Esc` | Dismiss dialog (window stays) |
| `Enter` | Activate focused button (default: Cancel → dismiss) |
| `Tab` / `Shift+Tab` | Move focus between Cancel and Close anyway |
| `Left` / `Right` arrows | Same as Tab / Shift+Tab |
| Left-click outside panel | Dismiss (Cancel) |
| Left-click on `Cancel` button | Dismiss |
| Left-click on `Close anyway` button | `event_loop.exit()` |
| Second `WindowEvent::CloseRequested` while dialog open | `event_loop.exit()` (rage-quit escape hatch — user clicked X again, they mean it) |
| Any other key / mouse event | Consumed by dialog, no underlying action |

`Cancel`-focused-by-default is the safety bias: if the user spammed Enter expecting the muscle-memory of a generic dialog, the safe outcome wins.

The rage-quit second-X-click is intentional — a user who fired off X and then *immediately* fires it again clearly wants out. Don't make them hunt for the button.

### 3.3 What programmatic exits do

The dialog gates ONLY `WindowEvent::CloseRequested`. The following exit paths bypass it (intentionally):

- `wgpu::SurfaceError::OutOfMemory` → `event_loop.exit()` (already at `window.rs:1217`)
- Panic / SIGTERM / SIGKILL → process termination, no dialog possible
- `cli` (`vibeflow --version` / `--import-colors`) → never enters the event loop

This matches user expectation: crash / kill behaviour shouldn't change; only "I clicked X" / "I hit Alt+F4" does.

## 4. Code structure

### 4.1 `crates/vibeflow/src/session/proc_watch.rs` additions

```rust
/// Read `/proc/<child_pid>/stat` and return field 7 (tpgid: the foreground
/// process group ID of the controlling terminal). Returns `None` on non-Linux,
/// on read error, or if the stat line is malformed.
///
/// Used by `PtySession::has_foreground_child` to detect when something other
/// than the shell itself holds the controlling terminal.
#[cfg(target_os = "linux")]
pub fn foreground_pgid(child_pid: i32) -> Option<i32> {
    let stat = std::fs::read_to_string(format!("/proc/{child_pid}/stat")).ok()?;
    parse_tpgid_from_stat(&stat)
}

#[cfg(not(target_os = "linux"))]
pub fn foreground_pgid(_child_pid: i32) -> Option<i32> {
    None
}

/// Parse field 7 (tpgid) from /proc/<pid>/stat. The trick: `comm` (field 2)
/// is paren-wrapped and may contain spaces, so split on the LAST `)` rather
/// than splitting the whole line on whitespace.
fn parse_tpgid_from_stat(stat: &str) -> Option<i32> {
    let after_comm = stat.rsplit_once(')')?.1.trim_start();
    // After `)` the fields are: state ppid pgrp session tty_nr tpgid …
    // tpgid is at index 4 (zero-based) in the post-`)` split.
    after_comm.split_whitespace().nth(4)?.parse().ok()
}
```

Tests: invalid PID returns None; self stat returns Some(self_pgid); malformed line returns None.

### 4.2 `crates/vibeflow/src/session/session.rs` additions

```rust
impl PtySession {
    /// True iff the controlling terminal's foreground process group is NOT
    /// the shell itself — i.e., the shell is running a subprocess that has
    /// terminal control (python3, vim, claude, make, etc.).
    ///
    /// Used by the v0.1.3 confirm-on-close dialog to identify "busy" tabs.
    pub fn has_foreground_child(&self) -> bool {
        let Some(child_pid) = self.child_pid() else {
            return false;
        };
        match proc_watch::foreground_pgid(child_pid) {
            Some(tpgid) => tpgid != child_pid,
            None => false, // fail-open: missing data ≠ busy
        }
    }
}
```

Tests: spawn a session, no child → false; spawn `sleep 30` in a session → true (within ~250ms); after `sleep` exits → false.

### 4.3 `crates/vibeflow/src/app.rs` additions

```rust
pub struct BusyTabInfo {
    pub tab_index: usize,
    pub display_label: String,
    pub state_label: String,
}

impl App {
    /// Walk all sessions and return a list of busy tabs. Empty if all tabs
    /// are idle (no FG process, no AI Working/Waiting state).
    ///
    /// display_label priority (most-informative wins):
    /// 1. AI tool name from `tracker.detected_tool()` if Working/Waiting (e.g. "claude", "codex").
    /// 2. FG process comm via `proc_watch::foreground_command_name` if `has_foreground_child`.
    /// 3. Fallback "process" (FG detection succeeded but comm read failed).
    pub fn busy_tabs(&self) -> Vec<BusyTabInfo> {
        self.sessions.iter().enumerate().filter_map(|(idx, sess)| {
            let busy_fg = sess.has_foreground_child();
            let tracker = sess.tracker_state();
            let busy_ai = matches!(tracker, TabState::Working | TabState::Waiting);
            if !busy_fg && !busy_ai {
                return None;
            }
            // AI tool name wins over raw process comm — "claude" is more
            // useful than "claude-cli" or whatever the binary basename is.
            let display_label = sess.detected_ai_tool()
                .filter(|_| busy_ai)
                .or_else(|| {
                    if busy_fg {
                        proc_watch::foreground_command_name(sess.child_pid()?)
                    } else {
                        None
                    }
                })
                .unwrap_or_else(|| "process".to_string());
            let state_label = if busy_ai {
                format!("{tracker:?}") // "Working" / "Waiting"
            } else {
                "running".to_string() // elapsed-time deferred to v0.1.4
            };
            Some(BusyTabInfo {
                tab_index: idx + 1, // 1-based for display
                display_label,
                state_label,
            })
        }).collect()
    }

    /// True iff close should trigger the confirm dialog.
    /// Confirm if multi-tab OR any tab busy.
    pub fn close_needs_confirmation(&self, config: &Config) -> bool {
        if !config.ui.confirm_on_close {
            return false;
        }
        self.sessions.len() > 1 || !self.busy_tabs().is_empty()
    }
}
```

### 4.5 `crates/vibeflow/src/render/confirm_close.rs` (new, ~250 LOC)

### 4.6 `crates/vibeflow/src/window.rs` changes

```rust
// New field on WindowApp:
confirm_close: Option<ConfirmCloseState>,

// CloseRequested handler:
WindowEvent::CloseRequested => {
    // Rage-quit: second close-request while dialog open → exit.
    if self.confirm_close.is_some() {
        tracing::info!("close requested while confirm open; exiting");
        event_loop.exit();
        return;
    }
    if !self.app.close_needs_confirmation(&self.config) {
        tracing::info!("close requested; no confirmation needed; exiting");
        event_loop.exit();
        return;
    }
    let busy = self.app.busy_tabs();
    tracing::info!(
        tab_count = self.app.session_count(),
        busy_count = busy.len(),
        "close requested; showing confirm dialog"
    );
    self.confirm_close = Some(ConfirmCloseState::new(busy));
    if let Some(window) = self.window.as_ref() {
        window.request_redraw();
    }
}
```

Key intercept: `try_consume_confirm_close_keypress` (mirrors `try_consume_about_keypress`) handles Esc / Enter / Tab / arrows.

Mouse intercept: `try_consume_confirm_close_mousepress` mirrors `try_consume_about_mousepress` but hit-tests the two buttons (Cancel = dismiss, Close anyway = `event_loop.exit()`).

Render call gains a `self.confirm_close.as_ref()` parameter.

Hoist priority: confirm_close intercepts BEFORE about_open AND BEFORE context_menu in mouse/key routing (per `lesson_keypress_clears_selection` + Stage 10 menu-intercept lesson — modal-most-on-top consumes first).

### 5.3 VNC smoke walk (manual, before merge)

1. Launch vibeflow with single idle bash tab → click X → window closes immediately (no dialog). **Regression check for v0.1.2 behavior on the common case.**
2. Open second tab (still idle) → click X → dialog shows "2 sessions are active" (idle tabs hidden, but multi-tab triggers the dialog by §2 logic — wait, the proposed UI shows busy tabs only; need to handle "multi-tab, none busy" case in the summary line). **See §6 open question.**
3. Single tab with `python3 -c "import time; time.sleep(60)"` → click X → dialog shows "Tab 1 (python3) — running" → Esc → dialog dismissed.
4. Same as #3 but click `Close anyway` button → window closes, python3 killed.
5. Three tabs (claude waiting, python sleep, idle bash) → click X → dialog shows 2 busy entries (claude + python), idle bash hidden → Esc → all three tabs intact.
6. Same as #5 but click X a SECOND time while dialog open → rage-quit exits immediately.
7. Set `confirm_on_close = false` in config → reload → all of the above close silently.

## 6. Open questions — RESOLVED 2026-05-27

1. **Multi-tab-all-idle dialog content** — RESOLVED: **(b)** keep "hide idle". Dialog renders `"{N} tabs are open. Close all?"` with no list region. Baked into §3.1 idle-multi-tab mode.
2. **Elapsed-time display for non-AI busy tabs** — RESOLVED: **defer to v0.1.4**. State label is just `"running"` for v0.1.3. Note in §4.3 comment.
3. **AI tools shown by name** — RESOLVED: **yes**, thread `detected_ai_tool()` from the session's tracker. `display_label` prefers AI tool name when Working/Waiting, falls back to FG-process comm, then to `"process"`. Implementation in §4.3.

Implementation requires one additional accessor on `PtySession`: `pub fn detected_ai_tool(&self) -> Option<String>` returning the tracker's currently-matched tool name (or `None` if no Tier-3 match active). The tracker already knows this internally — surface it.
