# vibeflow v0.1.4 — tab rename: select-all on entry (#8)

**Date:** 2026-06-01
**Status:** Design approved, implementing
**Issue:** [#8](https://github.com/bjhengen/vibeflow/issues/8)

## Problem
When a tab's name is wider than the tab, starting a rename renders the edit caret
**off-tab** (over the next tab or beyond). The rendered title text is width-clipped
(`render/tabs.rs:785`), but the caret is not: `caret_x = title_x_start + chars_before * cell_w`
(`tabs.rs:707-708`), and `start_rename` seeds `cursor_pos = title.len()` (the end). So the
caret sits past the clipped text until the user backspaces enough characters to bring it back
into the tab. Only then is the rename usable.

## Fix (user-specified)
On entering rename, **select the entire buffer**. The first keystroke or Backspace overwrites
everything; arrow/Home/End deselect (collapse) without clearing. The whole name is shown
highlighted with **no caret**, so the off-tab caret never appears on entry — and the common
case (replace the whole name) needs zero navigation.

## Design

### State (`render/tabs.rs`)
Add a field to `RenameInputState`:
```rust
/// True from rename entry until the first edit/navigation. While set, the whole
/// buffer is shown selected (highlighted, no caret) and the first insert/Backspace
/// replaces it. Cleared by any insert, Backspace/Delete, or cursor movement.
pub select_all: bool,
```
`start_rename` (`window.rs`) sets `select_all: true` (cursor_pos stays at `buffer.len()`).

### Edit logic — extracted & testable (`window.rs`)
The rename edits currently live inline in `handle_rename_keyboard` (which needs a full
`WindowApp`), so the existing tests *duplicate* the logic instead of exercising it. Extract them
to an inherent `impl RenameInputState` in `window.rs` (next to `prev_grapheme`/`next_grapheme`),
and make `handle_rename_keyboard` a thin winit-`Key` → method translator:

- `insert_str(&str)`: if `select_all` → `buffer.clear(); cursor_pos = 0; select_all = false;` then insert at `cursor_pos`.
- `backspace()`: if `select_all` → `clear; cursor_pos = 0; select_all = false;` (return); else delete previous grapheme.
- `delete()`: if `select_all` → same clear; else delete next grapheme.
- `move_left()` / `move_home()`: if `select_all` → `select_all = false; cursor_pos = 0;` (keep text); else move/home.
- `move_right()` / `move_end()`: if `select_all` → `select_all = false; cursor_pos = buffer.len();` (keep text); else move/end.

Enter → commit, Escape → cancel: unchanged.

### Render (`render/tabs.rs`, `build_rects`)
When `select_all` and `!buffer.is_empty()`:
- Draw a selection-highlight rect behind the title line, from `title_x_start`, width =
  `min(buffer_char_count * cell_w, text_area_width)` where
  `text_area_width = (tab.body.x + tab.body.w - close_button.w - 4) - title_x_start` (the same
  clip bound the text uses), height = `cell_h`.
- **Skip** the caret rect.

Otherwise: current caret behavior (caret at `cursor_pos`, blink-gated). The residual — typing a
*new* name longer than the tab pushes the caret off-tab again — stays **deferred** (clamp later
if it bites).

### Click during rename — unchanged
Clicking anywhere during a rename still **cancels** it (`window.rs:2034`, `:2063`). No
click-to-position-caret in the label (would need pixel→byte mapping + reintroduce long-name
caret math). To edit mid-name instead of overwriting, deselect with ←/Home/→/End, then type.

## Testing (TDD)
Unit tests in `window.rs` against the extracted `RenameInputState` methods (real production
logic, not duplicated):
1. `select_all` + `insert_str("x")` → buffer `"x"`, cursor 1, `select_all` false.
2. `select_all` + `backspace()` → buffer empty, cursor 0, `select_all` false.
3. `select_all` + `move_left()`/`move_home()` → `select_all` false, cursor 0, buffer unchanged.
4. `select_all` + `move_right()`/`move_end()` → `select_all` false, cursor `len`, buffer unchanged.
5. Non-`select_all` insert/backspace/move behave as before (rewrite the existing
   logic-duplicating tests to call the new methods).
6. Multibyte safety (`café`) preserved for backspace/delete/move.

Render/visual highlight + the off-tab-caret-gone-on-entry is VNC-smoke verified (winit render
isn't unit-testable).

## Non-goals
- Click-to-position caret in the label.
- Clamping the caret for a freshly typed over-long name (deferred residual).
- Partial text selection (only all-or-nothing, matching the requested behavior).
