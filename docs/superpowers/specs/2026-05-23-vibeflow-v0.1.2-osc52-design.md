## 1. Scope & non-goals

**In scope (v0.1.2):**

1. Parse OSC 52 write sequences in `crates/vibeflow/src/session/osc.rs`. Emit a new `OscEvent::Osc52Write { selection, text }` event.
2. Supported selections: `c` (CLIPBOARD), `p` (PRIMARY), `s` (BOTH). Multiple-letter combinations like `cp` interpreted as set-union.
3. Read requests (`OSC 52 ; <sel> ; ? BEL`) silently ignored: `tracing::debug!` logs them, no clipboard response sent.
4. Payload cap: 100 KB of raw text (after base64 decode). Sequences carrying more are truncated to 100 KB with a `tracing::warn!`.
5. Bump `MAX_OSC_LEN` from 4096 to 131_072 to accommodate base64-encoded payloads + small overhead.
6. Hook `Osc52Write` into the `OscEvent` consumer in `crates/vibeflow/src/window.rs` — dispatches to existing `crate::clipboard::write_clipboard` / `crate::clipboard::write_primary` (added in Stage 8).
7. Re-add the OSC 52 line to README, explicitly scoped to "write only — read intentionally unimplemented for security."

**Out of scope (with rationale):**

- **OSC 52 read** — significant security risk (any TUI app in any tab can silently exfiltrate the local clipboard). Skipping read matches xterm / foot / wezterm defaults. If user demand surfaces, an opt-in `[clipboard] osc52_read = true` config flag can land in v0.1.3.
- **Cut-buffer selections** (`0`-`7`, `q`) — rarely used in modern TUIs; ignored silently.
- **Indicator visual prominence** — dropped at brainstorm time (see above). Status quo accepted.
- **Per-OSC-code length caps** — global `MAX_OSC_LEN` bump is simpler and uniform; OSC 1338/133/0/2 frames remain small in practice.

## 2. Selection handling

The selection field is a string of one-or-more letters; each letter targets one buffer:

| Letter | Buffer |
|---|---|
| `c` | CLIPBOARD (system clipboard, what Ctrl+V pastes) |
| `p` | PRIMARY (X11 primary selection, middle-click paste) |
| `s` | BOTH (set-union of `c` and `p`) — xterm convention |
| `q`, `0`..`7` | cut-buffers — IGNORED (not supported) |

Combined letters (e.g. `cp`) act as set-union. Unknown / unsupported letters are filtered out; if nothing remains, the write is a no-op (still parsed successfully — not an error).

New enum in `osc.rs`:
```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Osc52Selection {
    Clipboard,
    Primary,
    Both,
}
```

`Both` covers `s`, `cp`, `pc`, and any letter-set with both `c` and `p` present.

## 3. Parser

**File:** `crates/vibeflow/src/session/osc.rs`

New helper:
```rust
enum Osc52ParseOutcome {
    Write {
        selection: Osc52Selection,
        text: String,
        truncated: bool,
    },
    ReadIgnored,
    Malformed,
}

const MAX_OSC52_RAW_BYTES: usize = 100 * 1024; // 100 KB after base64 decode

fn parse_52_body(body: &str) -> Osc52ParseOutcome {
    // body is the part after "52;" — e.g. "c;SGVsbG8=" or "c;?"
    let Some((sel_str, payload)) = body.split_once(';') else {
        return Osc52ParseOutcome::Malformed;
    };
    let selection = parse_selection(sel_str);

    if payload == "?" {
        return Osc52ParseOutcome::ReadIgnored;
    }

    use base64::Engine;
    let decoded = match base64::engine::general_purpose::STANDARD.decode(payload) {
        Ok(d) => d,
        Err(_) => return Osc52ParseOutcome::Malformed,
    };

    let (text_bytes, truncated) = if decoded.len() > MAX_OSC52_RAW_BYTES {
        (&decoded[..MAX_OSC52_RAW_BYTES], true)
    } else {
        (&decoded[..], false)
    };

    let text = String::from_utf8_lossy(text_bytes).into_owned();
    Osc52ParseOutcome::Write { selection, text, truncated }
}

fn parse_selection(s: &str) -> Osc52Selection {
    let mut has_c = false;
    let mut has_p = false;
    for ch in s.chars() {
        match ch {
            'c' => has_c = true,
            'p' => has_p = true,
            's' => return Osc52Selection::Both,
            _ => {}
        }
    }
    match (has_c, has_p) {
        (true, true) => Osc52Selection::Both,
        (true, false) => Osc52Selection::Clipboard,
        (false, true) => Osc52Selection::Primary,
        (false, false) => Osc52Selection::Clipboard, // safe default
    }
}
```

**Hook into the dispatcher:** the existing `try_parse_known_osc` (or equivalent — verify name at task time) routes by leading code. Add the `52` arm alongside the existing `0`, `2`, `133`, `1338` arms. On `Write { truncated: true }`, additionally emit `tracing::warn!(bytes = MAX_OSC52_RAW_BYTES, "OSC 52 write truncated")` before returning the event.

`ReadIgnored` emits `tracing::debug!("OSC 52 read request ignored (security)")` and is returned as no event (or, equivalently, as `OscEvent::Passthrough` if pass-through semantics are preferred).

`Malformed` emits `tracing::debug!("OSC 52 malformed; ignoring")` and returns no event.

## 4. Length cap

Change `crates/vibeflow/src/session/osc.rs`:
```rust
// Before:
const MAX_OSC_LEN: usize = 4096;
// After:
const MAX_OSC_LEN: usize = 131_072; // 128 KB — accommodates OSC 52 payloads
```

**Rationale:** the prior 4096 was conservatively chosen at Stage 2 when only OSC 0/2/133/1338 were in scope (all tiny). OSC 52 with a 100 KB raw cap requires ~134 KB envelope after base64; 128 KB tells xterm-spec implementations "we accept up to ~96 KB raw" which covers the common-case `vim "+y` of a whole file under 100 KB. Memory per active session grows by 128 KB only when an OSC sequence of that size is actively being buffered — idle sessions don't allocate.

Existing tests asserting the old constant value (if any) must be updated. `cargo test` will surface them.

## 5. Clipboard write integration

**File:** `crates/vibeflow/src/clipboard.rs` (small additive change) + `crates/vibeflow/src/window.rs` (new match arm).

**clipboard.rs gap:** the existing public API is `Clipboard::copy(&mut self, text: &str)` and `Clipboard::copy_primary(&mut self, text: &str)`. The `copy` method broadcasts to BOTH system clipboard AND primary when the user's `primary_enabled` flag is true. That's correct behavior for Ctrl+Shift+C (one user gesture = both buffers), but it violates OSC 52's per-selection semantic — `OSC 52 ; c ; ...` MUST touch only the system clipboard, never primary, regardless of user config.

Add one new method:
```rust
/// Set the system clipboard ONLY, never touching the primary selection.
/// Used by OSC 52 to respect the protocol's per-selection semantic.
///
/// # Errors
/// Propagates `arboard` errors. The caller logs at `warn` and proceeds.
pub fn copy_clipboard_only(&mut self, text: &str) -> Result<()> {
    self.inner.set_text(text)?;
    Ok(())
}
```
This is a strict subset of `copy()` — no `primary_enabled` consultation, no LinuxClipboardKind::Primary branch. ~6 LOC.

**window.rs new match arm** in the existing `OscEvent` consumer:
```rust
OscEvent::Osc52Write { selection, text } => {
    let want_clipboard = matches!(selection, Osc52Selection::Clipboard | Osc52Selection::Both);
    let want_primary   = matches!(selection, Osc52Selection::Primary   | Osc52Selection::Both);
    if want_clipboard {
        if let Err(e) = self.clipboard.copy_clipboard_only(&text) {
            tracing::warn!(error = %e, "OSC 52 write to clipboard failed");
        }
    }
    if want_primary {
        if let Err(e) = self.clipboard.copy_primary(&text) {
            tracing::warn!(error = %e, "OSC 52 write to primary selection failed");
        }
    }
}
```

(`self.clipboard` is the already-extant `Clipboard` instance held by `WindowApp` since Stage 8.)

## 9. Risks

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| Adversarial TUI spams 100 KB writes | low | clipboard churn / arboard load | The 100 KB cap + best-effort write IS the mitigation. Real-world vim copies are a few hundred bytes. |
| Some TUI apps expect OSC 52 read for sync | low | feature gap | Skipping read is xterm-compatible. If users complain, v0.1.3 adds opt-in config gate (per the read brainstorm option B not chosen this round). |
| `MAX_OSC_LEN` bump masks a parser bug in oversize handling | low | denial of service if parser doesn't bound right | OSC dispatcher already terminates on terminator byte; the bump only changes the upper-buffer cap. Existing OSC 133/1338 tests still pass after the bump. |
| `arboard` write fails on Wayland under specific conditions | medium | OSC 52 no-ops silently | Warn-log surfaces failures. Stage 8 already mitigates this for the explicit Ctrl+C / right-click-copy paths. |
| Test that uses arboard fails in headless CI | medium | CI red | Integration test gated with `#[cfg(not(ci_no_display))]` or uses a test-mode clipboard backend. |
| Selection parser accepts `s` mid-letter-string and bails | low | wrong selection | `parse_selection` handles `s` as immediate return for `Both`; combined `cs` / `sc` strings short-circuit on `s`. Acceptable since `s` already means BOTH. |
