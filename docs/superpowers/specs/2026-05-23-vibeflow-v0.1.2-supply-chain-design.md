# vibeflow v0.1.2 — Supply-chain + CI (Spec B) — design spec

**Date:** 2026-05-23
**Status:** Approved (brainstorm), pending implementation plan
**Branch base:** `main` @ `71c1c25` (v0.1.2 logging spec committed)
**Target release:** v0.1.2
**Sibling specs:** Render (`2026-05-23-vibeflow-v0.1.2-render-design.md`, committed `a343c3e`), Logging (`2026-05-23-vibeflow-v0.1.2-logging-design.md`, committed `71c1c25`), About (`2026-05-20-vibeflow-about-version-design.md`, committed `5dc1a6e`), UX (Spec C, to-write).

Close the open supply-chain and CI items from the Codex release review (`RELEASE_REVIEW.md`, findings #2 and #8), plus prevent the v0.1.1 version-mismatch slip from recurring.

Four distinct concerns:
1. **SHA-pin all GitHub Actions** — replace mutable `@vN` tags with immutable commit SHAs across both workflows. (Codex #2 leftover)
2. **Build provenance attestation + SBOM** — SLSA-3 attestation on the AppImage and a CycloneDX SBOM, both attached to the GitHub Release. (Codex #2 leftover)
3. **Cargo↔npm version-equality CI check** — assert workspace Cargo version == `bindings/npm/package.json` version on every CI run. (Lesson from v0.1.1 publish-time slip; fix landed at `9d6dea1`.)
4. **Config-value bounds** — clamp out-of-range user-supplied config values to sensible bounds, with a tracing warn naming the violated key. (Codex #8)

## 1. Scope & non-goals

**In scope (v0.1.2):**

1. All 6 actions currently in use across `.github/workflows/release.yml` + `.github/workflows/ci.yml` are SHA-pinned, each annotated with a trailing `# vX.Y.Z` comment naming the tag at pin time.
2. `release.yml` gains a build-provenance attestation step using `actions/attest-build-provenance@<sha>` after AppImage build, with the required `id-token` + `attestations` permissions.
3. `release.yml` gains an SBOM generation step using `anchore/sbom-action@<sha>`; the resulting `vibeflow-x86_64.sbom.cdx.json` is uploaded alongside the `.AppImage` and `.sha256` in the GitHub Release.
4. `ci.yml`'s `packaging` job gains a ~10-line shell step asserting `cargo metadata` version for `vibeflow-protocol` equals `bindings/npm/package.json` version.
5. New module `crates/vibeflow/src/config/bounds.rs` houses per-knob const ranges + a `clamp_with_warn` helper. Each existing `apply_*` function in `config/mod.rs` routes through it.
6. Theme file size cap (`main.rs::run_import_colors`) and startup theme-load count cap (`theme/registry.rs`).

**Out of scope (with rationale):**

- **Dependabot config for SHA bumps** — adds maintenance burden, marginal value while we ship infrequently. Manual quarterly bump is fine; revisit at v0.1.3.
- **`actionlint` CI integration** — value comes mostly from catching malformed YAML; with SHAs pinned by hand and reviewed, the failure mode is narrow. Defer.
- **`cosign`/Sigstore signing of release artifacts** — attestation is the v0.1.2 standard; full signing is a step beyond. v0.2 candidate.
- **`cargo-audit` / `cargo-deny`** — separate concern (vulnerability scanning, not supply chain hardening). v0.2 candidate.
- **Reproducible builds** — not a v0.1 commitment.
- **Per-knob TOML schema validation beyond ranges** (e.g. mutually-exclusive flags, structural constraints) — current schema-level validation is adequate; bounds are an additive layer.

## 3. SLSA build provenance attestation

**File:** `.github/workflows/release.yml`

Add a new step between "AppImage integrity check (headless-safe)" and "Publish AppImage checksum":

```yaml
- name: Attest build provenance for AppImage
  uses: actions/attest-build-provenance@<sha>  # v2.x.y
  with:
    subject-path: vibeflow-x86_64.AppImage
```

Extend the existing `permissions` block on the `appimage` job (currently only `contents: write`):
```yaml
permissions:
  contents: write       # existing
  id-token: write       # new — required by attest-build-provenance for OIDC
  attestations: write   # new — required to write the attestation back to the repo
```

**What this produces:** a SLSA Level 3 provenance attestation linked to the repo + workflow + commit + AppImage SHA-256. Verifiable post-release with:
```sh
gh attestation verify vibeflow-x86_64.AppImage --repo bjhengen/vibeflow
```

**Validation gate:** before the real v0.1.2 tag push, push a `v0.1.2-rc.1` tag to drive a full release dry-run. Confirm:
- Attestation step succeeds.
- `gh attestation verify` succeeds against the rc AppImage.

If either fails, fix in the spec/plan before the real push.

## 4. CycloneDX SBOM

**File:** `.github/workflows/release.yml`

Add a new step between "Publish AppImage checksum" and "Extract release notes from CHANGELOG":

```yaml
- name: Generate SBOM (CycloneDX)
  uses: anchore/sbom-action@<sha>  # v0.x.y
  with:
    path: ./target/release/vibeflow
    format: cyclonedx-json
    output-file: vibeflow-x86_64.sbom.cdx.json
```

Extend the existing `softprops/action-gh-release@<sha>` `files:` list:
```yaml
files: |
  vibeflow-x86_64.AppImage
  vibeflow-x86_64.AppImage.sha256
  vibeflow-x86_64.sbom.cdx.json   # new
```

**What this produces:** a CycloneDX JSON SBOM enumerating every dependency baked into the release binary (direct + transitive). Useful for consumers running supply-chain policy checks; satisfies many enterprise procurement asks.

The SBOM is generated FROM the release binary (`target/release/vibeflow`) rather than from `Cargo.lock` because Anchore's syft introspects the actual binary contents — picks up vendored deps + statically linked C libraries that `Cargo.lock` alone would miss.

## 5. Cargo↔npm version-equality CI check

**File:** `.github/workflows/ci.yml`

Add a new step to the existing `packaging` job, immediately after the "Verify Cargo packages include LICENSE..." step:

```yaml
- name: Verify Cargo workspace version matches npm package.json version
  run: |
    set -euxo pipefail
    CARGO_VER=$(cargo metadata --no-deps --format-version 1 --offline 2>/dev/null \
      | python3 -c "import json,sys; m=json.load(sys.stdin); \
                    p=[x for x in m['packages'] if x['name']=='vibeflow-protocol'][0]; \
                    print(p['version'])")
    NPM_VER=$(python3 -c "import json; print(json.load(open('bindings/npm/package.json'))['version'])")
    if [ "$CARGO_VER" != "$NPM_VER" ]; then
      echo "::error::Cargo vibeflow-protocol version ($CARGO_VER) != npm package.json version ($NPM_VER)"
      exit 1
    fi
    echo "Versions match: $CARGO_VER"
```

**Why `vibeflow-protocol` is the source of truth:** the npm package wraps the same wire-protocol logic as the Rust crate; they MUST move together to keep the contract identical. The `vibeflow` (terminal) crate has no npm counterpart — its version moves with `vibeflow-protocol`'s in the workspace, so checking `vibeflow-protocol` is sufficient.

**Smoke-test the check:** before merging the CI change, temporarily mismatch the two versions on a branch and confirm CI fails with the expected error message. Restore the versions before merge.

## 6. Config-value bounds

**New file:** `crates/vibeflow/src/config/bounds.rs`

**Per-knob ranges:**

| Knob | Min | Max | Rationale |
|---|---|---|---|
| `ai.heuristic_silence_ms` | 100 | 60_000 | <100 ms thrashes the /proc poll; >60 s defeats the silence-detection purpose. |
| `ai.stale_state_timeout_s` | 5 | 3_600 | <5 s misfires on slow processes; >1 h irrelevant for interactive state. |
| `ai.debounce_ms` | 50 | 10_000 | Typical 100–500 ms. <50 ms is jitter; >10 s is sluggish. |
| `ai.foreground_check_interval_ms` | 100 | 30_000 | /proc poll cadence. |
| `ai.explicit_stale_state_s` | 10 (or 0 = off) | 3_600 | 0 disables the fuse per existing semantic. Otherwise 10 s lower (anything shorter races the user's keystroke), 1 h upper. |
| `bell.debounce_ms` | 50 | 10_000 | Matches debounce range. |
| `scrollback.history_lines` | 1 | 1_000_000 | Existing `.max(1)` lower bound. 1 M lines ≈ ~100 MB grid memory — realistic ceiling for desktop RAM. |
| `scrollback.wheel_lines_per_detent` | 1 | 100 | Existing `.max(1)` lower bound. >100 lines/detent is a UI fail. |
| `scrollback.scrollbar_fade_ms` | 0 | 60_000 | 0 disables fade; >1 min is silly. |
| imported theme file size | n/a | 262_144 bytes (256 KB) | iTerm2 themes ~10 KB; cap with 25× margin. |
| themes loaded at startup count | n/a | 50 | Startup scan limit; warn on overage and drop the rest alphabetically. |

**`clamp_with_warn` helper:**
```rust
//! Per-knob bounds for user-supplied config values. Out-of-range values
//! are clamped to the nearest bound, with a single tracing::warn naming
//! the violated key + provided value + applied bound. Config still loads.

use std::fmt::Display;

pub fn clamp_with_warn<T>(key: &str, value: T, min: T, max: T) -> T
where
    T: PartialOrd + Copy + Display,
{
    if value < min {
        tracing::warn!(
            key = %key, value = %value, min = %min,
            "config value below minimum; clamped to min"
        );
        min
    } else if value > max {
        tracing::warn!(
            key = %key, value = %value, max = %max,
            "config value above maximum; clamped to max"
        );
        max
    } else {
        value
    }
}
```

**Wiring** — modify each existing `apply_*` function in `config/mod.rs`:
```rust
// Before:
if let Some(v) = schema.heuristic_silence_ms {
    resolved.heuristic_silence_ms = v;
}
// After:
if let Some(v) = schema.heuristic_silence_ms {
    resolved.heuristic_silence_ms = bounds::clamp_with_warn(
        "ai.heuristic_silence_ms", v,
        bounds::AI_HEURISTIC_SILENCE_MS_MIN, bounds::AI_HEURISTIC_SILENCE_MS_MAX,
    );
}
```

Per-knob constants live in `bounds.rs`. Existing lower-bound `.max(1)` calls (`apply_scrollback`) are replaced by `clamp_with_warn` calls using the appropriate constants.

**Special case: `explicit_stale_state_s`** — 0 disables the fuse (Section 3 of v0.1's docs); skip clamping when value == 0. Otherwise clamp to 10..=3600. Single `if v != 0 { … }` guard wrap.

**Theme file size cap** (`crates/vibeflow/src/main.rs::run_import_colors`):
```rust
const MAX_THEME_FILE_BYTES: u64 = 262_144; // 256 KB
let meta = std::fs::metadata(in_path).ok();
if let Some(meta) = meta {
    if meta.len() > MAX_THEME_FILE_BYTES {
        eprintln!(
            "{path_str}: file size {} bytes exceeds cap {} bytes; refusing to import",
            meta.len(), MAX_THEME_FILE_BYTES
        );
        std::process::exit(1);
    }
}
// existing std::fs::read(in_path) call follows
```

**Theme count cap** (`crates/vibeflow/src/theme/registry.rs`):
```rust
const MAX_THEMES_AT_STARTUP: usize = 50;
// Inside the scan loop that collects theme files:
let mut entries: Vec<_> = std::fs::read_dir(themes_dir)?
    .filter_map(Result::ok)
    .filter(|e| e.file_name().to_string_lossy().ends_with(".toml"))
    .collect();
entries.sort_by_key(|e| e.file_name());
if entries.len() > MAX_THEMES_AT_STARTUP {
    let dropped: Vec<_> = entries[MAX_THEMES_AT_STARTUP..]
        .iter().map(|e| e.file_name().to_string_lossy().into_owned()).collect();
    tracing::warn!(
        cap = MAX_THEMES_AT_STARTUP, dropped_count = dropped.len(),
        dropped_names = ?dropped,
        "config: theme directory has more themes than cap; dropping excess (alphabetical)"
    );
    entries.truncate(MAX_THEMES_AT_STARTUP);
}
// existing per-entry parse loop follows
```

## 9. Risks

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| SHA pin becomes stale; no auto-bump | medium | toolchain drift; security updates missed | Note in CHANGELOG; manual quarterly bump tracked in CLAUDE.md or a recurring task. Dependabot in v0.1.3. |
| `actions/attest-build-provenance` step fails on first try | medium | release blocked | `v0.1.2-rc.1` validation tag before real v0.1.2 push. |
| SBOM action breaks on cyclonedx schema change | low | SBOM gen errors | SHA-pin protects us; rev when validated. |
| Bound table tuning is bikeshed-prone | medium | brainstorm friction | Bounds are runtime-tunable post-v0.1.2 by editing constants; defaults are conservative; not load-bearing. |
| Theme count cap silently drops user's themes | low | confusion | Warn names dropped theme files. Users can curate `~/.config/vibeflow/themes/`. |
| `cargo metadata --offline` fails in CI if cache missing | low | CI flake | First CI run after lockfile change populates cache; subsequent runs hit `--offline` happily. Drop `--offline` if it causes friction. |
| Theme size check uses `std::fs::metadata` which can race with the read | very low | TOCTOU race | Theme import is a deliberate user action with no adversary; race-window is microseconds. Acceptable. |
