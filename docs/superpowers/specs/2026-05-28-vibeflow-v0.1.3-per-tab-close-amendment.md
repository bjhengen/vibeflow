# vibeflow v0.1.3 — Per-tab close amendment

**Date:** 2026-05-28
**Status:** Approved (chat)
**Parent spec:** `docs/superpowers/specs/2026-05-27-vibeflow-v0.1.3-confirm-close-design.md` @ `3155e92`
**Driven by:** 2026-05-28 VNC smoke walk — Brian noticed window-close confirms when a tab is busy, but Ctrl+W on a busy tab closes silently. Same risk vector; pulled forward from the original spec's "out of scope" list (§1).

---

## 1. Scope

**In:** confirmation dialog for the three remaining close paths that bypass `WindowEvent::CloseRequested`:

1. `Shortcut::CloseTab` — Ctrl+W (keyboard).
2. `TabBarHit::TabClose(idx)` — clicking the X on a tab in the tab bar.
3. `MenuAction::CloseOtherTabs` — context-menu "Close Other Tabs".

**Out:** any other close path (we don't know of others). External signals (SIGINT etc.) still terminate immediately.

## 2. ConfirmCloseScope

```rust
pub enum ConfirmCloseScope {
    Window,
    SingleTab { tab_index: usize },       // 0-based index into App.tabs
    OtherTabs { keep_tab_index: usize },  // 0-based; close everything else
}
```

`ConfirmCloseState` gains `pub scope: ConfirmCloseScope`. The existing constructor `ConfirmCloseState::new(busy, tab_count)` defaults `scope = Window` (backwards-compatible for the existing call site + tests). A second constructor `ConfirmCloseState::with_scope(busy, tab_count, scope)` covers the new paths.

## 3. Per-scope copy

| Scope            | Title                  | Confirm button       | Body (busy tabs in list)            |
|------------------|------------------------|----------------------|-------------------------------------|
| Window           | "Close vibeflow?"      | "Close Window"       | as in v0.1.3 §3                     |
| SingleTab(idx)   | "Close this tab?"      | "Close Tab"          | shows one BusyTabInfo for idx       |
| OtherTabs(keep)  | "Close other tabs?"    | "Close Other Tabs"   | shows BusyTabInfos for all ≠ keep   |

Cancel button label stays "Cancel" everywhere.

## 4. "Needs confirmation?" logic, per scope

| Scope            | Confirm if …                                                                     |
|------------------|----------------------------------------------------------------------------------|
| Window           | (existing) tab_count > 1 OR any tab busy                                         |
| SingleTab(idx)   | that tab is busy (foreground subprocess OR tracker_state ∈ {Working, Waiting})   |
| OtherTabs(keep)  | tabs_being_closed_count > 1 OR any of those tabs is busy                         |

`confirm_on_close = false` short-circuits all three to `false` (same as today).

## 5. App API additions

```rust
impl App {
    pub fn tab_busy_info(&self, idx: usize) -> Option<BusyTabInfo>;
    pub fn tab_close_needs_confirmation(&self, idx: usize, ui: &Ui) -> bool;
    pub fn tabs_busy_except(&self, keep_idx: usize) -> Vec<BusyTabInfo>;
    pub fn close_others_needs_confirmation(&self, keep_idx: usize, ui: &Ui) -> bool;
}
```

`tab_busy_info` mirrors the per-tab logic baked into `busy_tabs()` (refactor: extract a shared helper, call it from both).

## 6. window.rs wiring

Replace each direct `self.app.close_tab(...)` (or `CloseOtherTabs` loop) at:

- `Shortcut::CloseTab` (line 852)
- `TabBarHit::TabClose` (line 828)
- `MenuAction::CloseOtherTabs` (line 343)

with:

```rust
let idx = /* target tab */;
if self.confirm_on_close && self.app.tab_close_needs_confirmation(idx, ...) {
    let busy = self.app.tab_busy_info(idx).into_iter().collect();
    self.confirm_close = Some(ConfirmCloseState::with_scope(
        busy, self.app.tabs().len(),
        ConfirmCloseScope::SingleTab { tab_index: idx },
    ));
    /* request_redraw */
} else {
    self.app.close_tab(idx);
}
```

(symmetric pattern for OtherTabs).

The confirm-button handler (today: `event_loop.exit()`) becomes a `match self.scope` that performs the right close action and clears `self.confirm_close = None`.

## 9. Non-goals (still)

- Multi-select close (Shift+click batch close): no UI for it; deferred.
- Per-tab "force close" shortcut: `confirm_on_close = false` covers always-off; no per-action override.
- Dialog stacking: only one dialog at a time. If a dialog is open and the user invokes another close path, ignore (current behavior already).
